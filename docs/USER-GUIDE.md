# 使用与升级

## 安装与打开

运行 `pnpm install`、`pnpm check` 后，通过 `pnpm pack --pack-destination dist` 生成安装包，在 DSH 插件页安装并启用 `dsh-superagent`。插件沿用官方原型的 DSH 0.2.1-alpha.2 接口基线，兼容范围见 package.json。

侧边栏入口为 **SuperAgent**。默认是概览，导航依次为概览、来源、触发、评估、执行、关于、设置。面板使用原型的 React 控件、DSH 主题变量和自动轮询。线程页展示消息时间线及订阅，任务页展示派工、报告、输入与执行状态。主会话及任务的执行会话均可在 DSH 中打开。

安装与启用是两个步骤。启用本项目的组合包 `dsh-superagent`。若安装后仍报 `dsh-superagent/lib/index.js` 等入口缺失，检查组合包选择。内部插件条目沿用原型命名，加载模块来自本包 `dsh-superagent`。

## 设置

设置位于最后一个标签，配置说明放在各字段和标题的 `?` 提示中。

- **执行**：通用 Worker 模型、并发数量和默认工作目录。模型与目录留空使用 DSH / 插件默认值。准备命令和命令限制为可选高级项。
- **来源**：飞书填写应用编号和密钥。到飞书后台开启机器人、长连接、接收消息事件及相应消息权限并发布应用。选择接收的群、是否主动观察及私聊开关。
- **评估**：配置可以发起工作的人、来源群/提及/发送者准入表和主动判断规则。飞书用户可以先发测试消息，再从名单中选择；也可按群成员同步名单。
- **更多设置**：编辑通用沟通、任务范围与交付要求，以及团队技能。按场景添加技能，例如“外文文章翻译”“开源项目调研”“知识库维护”，写清适用条件、目标、约束和交付标准。Worker 通过原型的技能机制按需读取，调度与订阅机制保持统一。
- **运行配置**：数据保存目录和上下文读取上限等，普通使用保持默认即可。

飞书新任务的候选过滤先做原型的三维准入，再检查关注/忽略关键词；关键词用逗号分隔，忽略优先。已经订阅的后续消息沿用原型直通与授权语义。语义层使用评估规则与可编辑内置提示词，不固定为某个行业或收录场景。

各类文本的读取角色、接单规则与派工的关系、场景技能示例及升级行为，见 [提示词与接单规则配置说明](PROMPTS.md)。

## 飞书应用与知识库

保存时验证应用身份，SDK 自动管理应用访问凭证并建立长连接。读取群内普通消息需要相应的全量消息权限，历史补收另需历史消息权限。知识库和文档操作还需要 Wiki/Docx API 权限及目标资源访问权限。

Worker 使用 `orchestrator_feishu_api` 操作已授权的飞书资源，沿用原型的任务、报告与交付流程。需要收录时，在团队技能中指定目标 Wiki 目录链接、拆解/翻译要求及文档结构。接口回执和回读结果是完成依据；来源、结构化报告和真实交付链接保留在任务及 DSH Session 中。

密钥单独保存在数据目录的 `feishu-credentials.json`，权限 0600。设置版本和模型上下文只保存应用编号与凭证版本标识。已保存的密钥留空保留，重新填写可更新。

## 会话与暂停

常驻 Router 为 `orchestrator-…` 会话；执行任务使用原型的 `worker-<ticket id>` 会话，关联到 DSH 工作区。主面板及任务详情中的“打开会话”会刷新宿主会话列表后打开目标。具体推理和工具操作在执行会话中，Router 负责统一回复入口消息。

暂停、停止、重试、人工提问与恢复均沿用原型语义。暂停拦住新派工、评估和投递，当前执行轮次可继续。停止会撤回当前任务。已订阅线程的后续消息直接进入 Worker，范围外的新请求由 Worker 交回 Router。关闭订阅与仅关注上下文可在任务/线程详情管理。

## 已交付工单的订阅轮询

工单交付后仍可保留线程订阅，用于接收后续补充。原型会持续轮询关联着活动工单的线程；对近期完成的工单，按最近消息或结束时间保留 14 天的轮询窗口。任务结束与取消订阅是两个不同操作。

0.2.0 的飞书 SDK 适配曾将消息 ID 数组编码为 `message_ids[]`，接口可能返回空列表，导致正常消息显示“原消息不可用或已删除”。0.2.1 改为飞书要求的重复同名参数，并区分查询无结果与明确删除。

更新后，下一轮成功读取会自动清除线程的旧轮询错误。无需删除消息或重新创建工单。遇到新的查询无结果提示时，可检查应用读取权限与来源范围；仅当飞书明确返回删除标记时提示已删除。

## 从 0.1 版本升级

默认数据目录为 `~/.dsh/superagent-general`。旧版 `settings.json` 的导入函数保留在 `src/app/legacy-import.ts`，但本分支的 Runtime 未调用它；升级前请备份，并按设置页手工迁移人员、群、关键词、模型和团队技能。

旧版 `superagent.sqlite` 与设置文件保留，原型引擎使用独立的 `orchestrator.sqlite`。旧版知识流水线没有创建 DSH Session，旧任务不会生成虚构会话。新版开始的工作统一通过原型 Worker 执行。旧运行记录和旧任务状态库暂未转换到原型领域模型。

## 守护与验证边界

进程守护由部署环境负责；本分支不包含 watchdog 入口。任务、订阅、Effect、Outbox 和模型额度恢复使用官方原型的机制。

飞书真实权限与资源写入仍需要使用自己的应用完成联调。配置目录含凭证，备份时需妥善保管。原型的执行工具运行在宿主授权的环境中，使用前应配置相应的工作范围。
